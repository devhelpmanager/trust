# WordPress-тема Trust

Тема сайта агентства «SEO, сайты, контекстная реклама» по макетам из этого репозитория.
Техническое задание — [`docs/TZ-WordPress-tema.md`](../docs/TZ-WordPress-tema.md),
инвентарь «макет → блок/шаблон» и план работ — [`docs/inventory.md`](docs/inventory.md).

## Что в папке

| Путь | Что это |
|---|---|
| `trust/` | Сама тема — эта папка копируется в `wp-content/themes/trust/` |
| `docs/inventory.md` | Какая секция какого макета каким блоком или шаблоном стала, план работ |
| `bin/local.sh` | Локальный стенд: WordPress + SQLite + SCF + WP-CLI |
| `composer.json`, `phpcs.xml.dist` | Проверка кода (WordPress Coding Standards) |
| `tests/` | Автотесты (Playwright): страницы, настройки, шапка, подвал, окно звонка, блоки, визуальная сверка с макетами |

## Требования

- WordPress 6.6 или новее (проверяется на 7.1), PHP 8.1 или новее (проверяется на 8.3).
- Плагин **Secure Custom Fields** из каталога WordPress.org. Без него сайт открывается, но блоки,
  поля и «Настройки сайта» не работают, а в админке висит уведомление со ссылкой на установку.
- Сборка не нужна: CSS, JS и шрифты лежат в теме готовыми.

## Установка на сервер

Команды выполняются по SSH на сервере от пользователя с правом `sudo` (или от root). Нужны
`git`, `rsync` и [WP-CLI](https://wp-cli.org/). WP-CLI запускается от имени владельца файлов
сайта (`sudo -u "$OWNER"`), чтобы плагин и тема не оказались принадлежащими root.

**1. Путь к сайту** — папка, где лежит `wp-config.php` (замените на свой):

```bash
SITE=/var/www/example.ru
```

Владелец файлов сайта (определяется сам) и переход в папку сайта. Команды WP-CLI от имени
владельца нужно запускать из папки сайта: из `/root` у него нет доступа, и часть команд падает с
`proc_open(): posix_spawn() failed: Permission denied`.

```bash
OWNER=$(stat -c '%U' "$SITE/wp-config.php") && cd "$SITE" && echo "Сайт: $SITE, владелец: $OWNER"
```

**2. Проверить инструменты.** Если какой-то команды нет, её нужно установить (для Ubuntu/Debian:
`sudo apt install git rsync`, WP-CLI — шаг 3):

```bash
git --version; rsync --version | head -1; wp --version --allow-root
```

**3. WP-CLI** — только если его нет:

```bash
curl -fsSLO https://raw.githubusercontent.com/wp-cli/builds/gh-pages/phar/wp-cli.phar && chmod +x wp-cli.phar && sudo mv wp-cli.phar /usr/local/bin/wp && wp --version --allow-root
```

**4. Скачать репозиторий** (один раз):

```bash
git clone --branch claude/happy-pascal-t7rcow --single-branch https://github.com/devhelpmanager/trust.git ~/trust
```

**5. Скопировать тему в WordPress** и отдать файлы владельцу сайта:

```bash
sudo rsync -a --delete ~/trust/wp-theme/trust/ "$SITE/wp-content/themes/trust/" && sudo chown -R "$OWNER": "$SITE/wp-content/themes/trust"
```

**6. Плагин Secure Custom Fields и тема:**

```bash
sudo -u "$OWNER" -- wp --path="$SITE" plugin install secure-custom-fields --activate
```

```bash
sudo -u "$OWNER" -- wp --path="$SITE" theme activate trust
```

**7. Постоянные ссылки** по ТЗ: статьи блога — `/blog/<ярлык>/`:

```bash
sudo -u "$OWNER" -- wp --path="$SITE" rewrite structure '/blog/%postname%/'
```

Если сайт обслуживает Apache (в том числе за nginx, как в FastPanel), нужен `.htaccess` с правилами
WordPress — иначе адреса вида `/kontakty/` отдают 404. WP-CLI записывает его стандартной функцией
WordPress (только блок `# BEGIN WordPress … # END WordPress`, остальное содержимое файла не трогает),
если сказать ему, что модуль `mod_rewrite` есть:

```bash
printf 'apache_modules:\n  - mod_rewrite\n' > /tmp/wp-cli-apache.yml && chmod 644 /tmp/wp-cli-apache.yml && sudo -u "$OWNER" -- env WP_CLI_CONFIG_PATH=/tmp/wp-cli-apache.yml wp --path="$SITE" rewrite flush --hard && cat "$SITE/.htaccess"
```

**8. Русский язык WordPress** (если установлен другой):

```bash
sudo -u "$OWNER" -- wp --path="$SITE" language core install ru_RU --activate
```

**9. HTTPS.** Если сайт открывается по `https://` (например, через Cloudflare), а в WordPress записан
адрес с `http://` — стили и скрипты будут заблокированы браузером. Перевести адреса в базе:

```bash
sudo -u "$OWNER" -- wp --path="$SITE" search-replace 'http://example.ru' 'https://example.ru' --all-tables
```

Если после этого браузер пишет «Слишком много переадресаций» (Cloudflare в режиме Flexible
обращается к серверу по http), WordPress нужно сообщить, что посетитель пришёл по https — строка
в `wp-config.php` перед «That's all, stop editing»:

```bash
grep -q HTTP_X_FORWARDED_PROTO "$SITE/wp-config.php" || sed -i "/That's all, stop editing/i if ( isset( \$_SERVER['HTTP_X_FORWARDED_PROTO'] ) && 'https' === \$_SERVER['HTTP_X_FORWARDED_PROTO'] ) { \$_SERVER['HTTPS'] = 'on'; }" "$SITE/wp-config.php"
```

### Демо-контент

Заполняет сайт заглушками из макетов (сейчас — «Настройки сайта», 26 страниц, меню шапки и
подвала, страница согласия и политика конфиденциальности для форм, первые экраны услуг, портфолио,
«О компании», «Команды», «Карьеры», «Контактов», «Отзывов», документов и «Вопросов SEO», блок
«Вопрос-ответ» на странице `/seo/audit/`, тарифы, текст, картинка и «Главная мысль» на `/seo/`, рубрики и теги блога, услуги, отрасли, отделы и темы вопросов, 9 кейсов
портфолио, 9 отзывов, 15 сотрудников, 6 вакансий, 21 вопрос; набор растёт с каждым шагом):

```bash
sudo -u "$OWNER" -- wp --path="$SITE" trust demo import
```

Повторный импорт не создаёт дублей и не трогает то, что вы изменили вручную (открыть страницу в
редакторе и нажать «Обновить» без правок — не изменение: такие страницы импорт обновляет). Если по
адресу демо-страницы уже есть ваша страница, она не меняется. Если в области меню уже стоит ваше меню,
демо-меню не ставится. Переименованная в демо-данных страница (поле `was` в `demo/pages.php`, например
«Сопровождение сайтов» → «Поддержка сайтов», `/site-support/`) получает новый адрес, а пункты меню
на неё — новый заголовок, если их не меняли вручную; редирект со старого адреса не создаётся.

Обновить то, что меняли вручную (ручные правки будут заменены): `--force` без значения — весь
демо-контент, со значением — перечисленное через запятую из строк «Пропущены»: адреса страниц,
ключи записей, термины `таксономия:ключ`, имена настроек:

```bash
sudo -u "$OWNER" -- wp --path="$SITE" trust demo import --force=seo/audit,karera,repair
``` Удалить демо-контент (изменённое вручную останется):

```bash
sudo -u "$OWNER" -- wp --path="$SITE" trust demo remove
```

### Обновление темы

Удобнее один раз сохранить на сервере скрипт обновления (путь к сайту — свой):

```bash
cat > /root/trust-update.sh <<'SH'
#!/usr/bin/env bash
# Обновление темы Trust из GitHub. Запуск: bash /root/trust-update.sh [--demo | --demo-force]
set -euo pipefail
SITE=/var/www/example_usr/data/www/example.ru
OWNER=$(stat -c '%U' "$SITE/wp-config.php")
cd "$SITE"
git -C /root/trust pull --ff-only
rsync -a --delete /root/trust/wp-theme/trust/ "$SITE/wp-content/themes/trust/"
chown -R "$OWNER": "$SITE/wp-content/themes/trust"
if [ "${1:-}" = "--demo" ]; then
	sudo -u "$OWNER" -- wp --path="$SITE" trust demo import
elif [ "${1:-}" = "--demo-force" ]; then
	sudo -u "$OWNER" -- wp --path="$SITE" trust demo import --force
fi
echo "Тема обновлена: $(git -C /root/trust log --oneline -1)"
SH
```

После каждого шага разработки:

```bash
bash /root/trust-update.sh
```

Если в отчёте шага сказано, что демо-контент пополнился, — с ключом `--demo`:

```bash
bash /root/trust-update.sh --demo
```

На этапе разработки, пока на сайте нет ценного контента, — `--demo-force`: весь демо-контент
обновляется, даже если его меняли вручную (страницы, записи, термины, настройки из демо, демо-меню
создаются заново). После запуска сайта этот ключ не использовать.

```bash
bash /root/trust-update.sh --demo-force
```

Тема копируется, а не подключается символической ссылкой: некоторые панели управления
хостингом запрещают веб-серверу ходить по ссылкам, и тогда стили и шрифты не загрузятся.

## Локальная разработка

Стенд: WordPress + SQLite (без MySQL) + Secure Custom Fields + WP-CLI, встроенный сервер PHP.
Нужны PHP 8.1+ с `pdo_sqlite`, `git`, `curl`, `unzip`. Всё скачивается с GitHub (официальные
репозитории WordPress, релиз SCF, сборка WP-CLI) в `~/wp-dev`, вне репозитория. Тема
подключается символической ссылкой, поэтому правки в `wp-theme/trust/` видны сразу.

```bash
wp-theme/bin/local.sh setup
```

```bash
wp-theme/bin/local.sh start
```

Сайт — http://localhost:8080/, админка — http://localhost:8080/wp-admin/ (`admin` / `admin`).
Остальные команды: `stop` — остановить сервер, `reset` — установить WordPress заново,
`wp <команда>` — WP-CLI на стенде (например, `wp-theme/bin/local.sh wp plugin list`).
Версии и папку можно поменять переменными `WP_VERSION`, `SCF_VERSION`, `TRUST_DEV_DIR`, `TRUST_PORT`.

Особенности стенда:
- `WP_DEBUG` включён, ошибки пишутся в `~/wp-dev/debug.log`, на экран не выводятся;
- внешние HTTP-запросы заблокированы (`WP_HTTP_BLOCK_EXTERNAL`), проверки обновлений и Gravatar
  отключены mu-плагином `wp-content/mu-plugins/trust-local.php` — он есть только на стенде;
- язык сайта `ru_RU` задан константой `WPLANG`: переводы ядра на стенд не скачиваются, поэтому
  админка на английском, а строки темы — на русском.

### Инструменты проверок

Один раз:

```bash
cd wp-theme && composer install
```

```bash
cd wp-theme/tests && npm install
```

Composer берёт пакеты через `git clone` (`preferred-install: source`), npm ставит `axe-core`,
`pixelmatch` и `pngjs` (сравнение снимков с макетами).
Playwright не ставится: используется установленный в системе (`require('playwright')`).

### Правила кода

- PHP — WordPress Coding Standards, префикс функций и хуков `trust_`, классы в пространстве
  имён `Trust\`, текстовый домен `trust`, исходный язык строк — русский.
- Видимые посетителю тексты, картинки и ссылки — только из админки (поля, настройки, меню).
  В коде — вёрстка, стили, логика и служебные строки интерфейса в `__()` / `esc_html__()`.
- Каждый блок — своя папка `blocks/<имя>/` со стилями и скриптом, которые подключаются только
  на страницах с этим блоком. Общий `main.css` — не больше ~40 КБ.

### Шрифты

Файлы взяты из npm-пакетов `@fontsource/unbounded@5.3.0`, `@fontsource/onest@5.3.1`,
`@fontsource/jetbrains-mono@5.3.0`: начертания из макетов, поднаборы кириллица, латиница и
расширенная латиница (в ней знак ₽). Браузер загружает только нужные поднаборы
(`unicode-range`). Лицензии — `assets/fonts/OFL-*.txt`.

## Проверки

Синтаксис PHP:

```bash
find wp-theme/trust -name '*.php' -print0 | xargs -0 -n1 php -l
```

Стандарты кода (WordPress Coding Standards + совместимость с PHP 8.1+), из папки `wp-theme`:

```bash
vendor/bin/phpcs
```

Дымовой тест на запущенном стенде:

```bash
node wp-theme/tests/smoke.js
```

Он проверяет главную (код ответа, язык, CSS и предзагрузка шрифтов, отсутствие emoji, jQuery и
служебных ссылок, загрузку шрифтов, ссылку «Перейти к содержимому», axe-core без нарушений
critical/serious), уведомление в админке без SCF, консоль браузера и журнал ошибок WordPress.
Скриншоты — в `wp-theme/tests/output/`.

Страница «Настройки сайта» (после `wp-theme/bin/local.sh wp trust demo import`):

```bash
node wp-theme/tests/settings.js
```

Проверяет вкладки и поля, демо-значения, сохранение без потерь и дублей, права: администратор видит
всё, редактор — всё, кроме кода карты, автор — страницу не открывает.

Шапка (на стенде с демо-контентом):

```bash
node wp-theme/tests/header.js
```

Проверяет данные из настроек, пункты меню, подсветку текущей страницы и раздела, подменю (мышь,
клавиатура, Esc, клик вне), раскладку на 1180/1179/760/520/390/280 px, зоны нажатия, axe-core и
совпадение с макетом `portfolio-blog-404/portfolio.html` на 1280 px (не больше 2 % пикселей; эталон
рисуется локальными шрифтами темы). Скриншоты и картинка разницы — в `tests/output/header-*.png`.

Мобильная шапка:

```bash
node wp-theme/tests/header-mobile.js
```

### Окно «Заказать обратный звонок»

- Открывается любой ссылкой или кнопкой с атрибутом `data-trust-callback` (так же будут работать
  кнопки в блоках). Стандартный `<dialog>`: фокус остаётся в окне, Esc закрывает только окно.
- Тексты — «Настройки сайта → Блоки по умолчанию». Текст по умолчанию виден в пустом поле серой
  подсказкой и не записывается в базу при сохранении: пустое поле всегда значит «текст темы».
- Галочка согласия ведёт на страницу из «Блоки по умолчанию → Страница согласия», строка под
  кнопкой — на политику из стандартной настройки «Настройки → Конфиденциальность».
- Пример номера в полях «Телефон» — `+1 000 000 00 00` (`Forms::phone_example()`, фильтр
  `trust_phone_example`).
- Заявка уходит без перезагрузки (модуль форм, см. «Формы и заявки»), окно показывает «Заявка
  отправлена»; при следующем открытии — снова пустая форма. Капчи в окне нет.

### Cookie и счётчики

Плашка cookie (`Trust\Cookie`, `template-parts/cookie-banner.php`, `assets/js/cookie.js`; макет
`seo-bloki/17-cookie.html`) появляется внизу экрана при первом визите: «Принять» — все категории,
«Принять только обязательные» и «Отклонить всё» — только обязательные. После выбора плашка
скрывается; видимой подсказки «Изменить» нет (правка заказчика), выбор озвучивается скринридеру
(скрытая строка `role="status"`). Открыть плашку снова —
ссылка на `#cookie-settings` (её можно добавить в любое меню как «Произвольную ссылку») или элемент
с атрибутом `data-trust-cookie-settings`. Без JavaScript плашки нет: без скриптов счётчики не работают.

Выбор хранится в cookie `trust_consent` (JSON: `v` — версия согласия, `necessary`, `analytics`,
`marketing`, `choice` — `all` / `necessary` / `none` / `custom`, `date`) на срок из настроек
(по умолчанию 365 дней). Решение принимается в браузере, поэтому кэш страниц не мешает.

«Настройки сайта → Cookie и счётчики» (только администратор): заголовок и текст плашки (слова в
`{фигурных скобках}` — ссылка на страницу политики), страница политики cookie, срок хранения выбора,
версия согласия (поменяли — плашка снова у всех), код счётчиков (аналитика) и код рекламных
пикселей. Код выводится внутри `<template>` и выполняется только после согласия на свою категорию —
сразу, без перезагрузки; при следующих визитах — сразу при загрузке. Если согласие отозвано,
страница перезагружается, cookie известных счётчиков (Метрика, Google, VK, Meta) удаляются.

Обязательные cookie темы: `trust_consent` (выбор) и `trust_source` (источник перехода для заявок,
90 дней) — ставятся без согласия.

Для блоков: `window.trustConsent` — `get()`, `has( 'analytics' )`, `set( { analytics, marketing }, choice )`,
`open()`; событие `trust:consent` на `window` после каждого сохранения выбора (блок «Настройки
cookie» на странице политики — шаг 4.15).

### Формы и заявки

Описание формы — `Trust\Forms::types()`: поля с правилами и сообщениями об ошибках (одни и те же
в браузере и на сервере), галочки согласий, нужна ли капча. Формы блоков добавляются фильтром
`trust_form_types` на шагах этих блоков. Разметка формы:

- `<form data-trust-form="{тип}" action="<?php echo esc_url( Trust\Forms::fallback_url() ); ?>" method="post">`;
- `Trust\Forms::hidden_fields( '{тип}' )` — тип, токен, nonce, поле-ловушка;
- у полей `data-error` (текст ошибки) и `aria-describedby` (элемент `.field__error` для него);
  тип поля — атрибутом `type` или `data-type="url|contact"`;
- `Trust\Forms::captcha( '{тип}' )` — место для капчи (если форме нужна и ключи введены);
- `Trust\Forms::status( '{тип}' )` — строка сообщений (и результат отправки без JavaScript);
- экран успеха — элемент с `id` из `data-success` у формы, кнопка «Отправить ещё» — `data-form-again`.

Скрипт `assets/js/forms.js` подключает такие формы сам (свой скрипт — атрибут
`data-trust-form-custom`, как у окна звонка) и даёт `window.trustForms`: `validate`, `check`,
`setError`, `submit`.

**Отправка:** `fetch` на `POST /wp-json/trust/v1/forms/{тип}`; без JavaScript — обычная отправка
на `admin-post.php` и возврат на ту же страницу с сообщением. Вместе с полями уходят адрес страницы
и источник перехода: cookie `trust_source` (UTM-метки, откуда пришёл, первая страница и время
первого визита; ставится скриптом при первом визите на 90 дней, никуда, кроме заявки, не уходит;
категория cookie — обязательные).

**Защита от спама** (`Trust\Forms\Protection`):

| Что | Как |
|---|---|
| Ловушка | Скрытое поле `trust_website`: заполнено — ответ «успешно», заявка не сохраняется |
| Время заполнения | Токен «время-подпись» (HMAC с солью сайта): не раньше 3 с от выдачи, не старше 12 ч. Скрипт берёт свежий токен при первом касании формы — кэш страниц не мешает |
| nonce | Действие `trust_form`; устарел — скрипт сам берёт новый и повторяет отправку |
| Частота | Не больше 8 отправок с одного IP за 10 минут (фильтр `trust_form_rate_limit`). За Cloudflare адрес берётся из `CF-Connecting-IP`, но только если запрос пришёл от сетей Cloudflare или от своего прокси на сервере |
| Капча | «Настройки сайта → Формы»: Google reCAPTCHA v2 («Я не робот») или Яндекс SmartCaptcha. Ответ проверяется на сервере секретным ключом; секрет на страницу не попадает; скрипт капчи грузится только после касания формы. Без ключей капча не показывается, формы работают |

**Заявки** (`Trust\Forms\Leads`, меню «Заявки», счётчик новых): тип формы, все поля (у выбора —
подпись варианта), страница отправки и её название, UTM-метки и источник, дата, статус («Новая»,
«В работе», «Закрыта»), факт согласия — какие галочки, дата и время, адрес и дата редакции
документа согласия. Список: колонки «Форма», «Имя», «Контакт», «Статус», «Дата», фильтры по форме
и статусу, массовая смена статуса и «Выгрузить в CSV» (UTF-8 с BOM, разделитель «;» — открывается
в Excel; значения, похожие на формулы, экранируются). Срок хранения — «Настройки сайта → Формы»:
заявки старше срока удаляются ежедневной задачей WP-Cron `trust_leads_cleanup` (пусто — не удалять).
После сохранения заявки — действие `trust_form_submitted` (по нему уходят уведомления).

**Уведомления** (`Trust\Forms\Notifications`, «Настройки сайта → Формы»):

| Канал | Когда уходит | Что |
|---|---|---|
| Письмо (`wp_mail`) | Всегда | Получатели формы → получатели по умолчанию → адрес администратора сайта. Тема «Новая заявка: {форма} — {имя или контакт}», простой текст: поля, UTM, откуда пришёл, страница, ссылка на заявку в админке. Имя отправителя — бренд; если контакт клиента — email, он в Reply-To |
| Telegram | Заданы токен бота и chat_id | Сообщение от бота (HTML): форма, поля, страница, ссылка на заявку |
| Вебхук CRM | Задан адрес | POST JSON (ниже), подпись в заголовке `X-Trust-Signature` |

Заявка сохраняется до уведомлений, ошибка канала её не отменяет. Уведомления уходят в конце запроса,
после ответа посетителю (на PHP-FPM — `fastcgi_finish_request`), поэтому медленный канал не
задерживает форму. Итог по каждому каналу записывается в заявку (`trust_notify`) и виден на её
экране в строке «Уведомления»; там же ссылка «Отправить уведомления ещё раз». Кнопка «Проверить
уведомления» на вкладке «Формы» отправляет тестовую заявку во все заданные каналы (в базе она не
сохраняется); если задан токен бота, а chat_id нет — показывает chat_id чатов, которые писали боту.

Как подключить Telegram: в Telegram откройте @BotFather → `/newbot` → токен вставьте в «Telegram:
токен бота» и сохраните. Напишите боту любое сообщение (или добавьте бота в группу и напишите там),
нажмите «Проверить уведомления» — тема покажет chat_id; вставьте его и сохраните.

Вебхук: `POST` на адрес из настроек, `Content-Type: application/json; charset=utf-8`, заголовки
`X-Trust-Event` (`lead.created`, у проверки — `lead.test`) и, если задан секрет,
`X-Trust-Signature: sha256=<HMAC-SHA256 тела запроса секретом, hex>`. Только внешние адреса:
внутренние адреса сервера (127.0.0.1, локальная сеть) отклоняются. Ответ 2xx — доставлено.

```json
{
  "event": "lead.created",
  "site": "https://example.com/",
  "sent_at": "2026-11-12T19:10:11+03:00",
  "lead": {
    "id": 123, "form": "callback", "form_label": "Обратный звонок",
    "title": "Обратный звонок: Анна", "created_at": "2026-11-12T19:10:11+03:00",
    "date": "12.11.2026 19:10", "status": "new", "name": "Анна", "contact": "+1 000 000 00 00",
    "fields": { "name": { "label": "Имя", "value": "Анна" }, "phone": { "label": "Телефон", "value": "+1 000 000 00 00" } },
    "page": { "url": "https://example.com/kontakty/", "title": "Контакты" },
    "source": { "utm_source": "yandex", "utm_medium": "cpc", "referrer": "https://…", "landing": "https://…", "at": "2026-11-12 11:00:00" },
    "consent": { "items": [ "Согласие на обработку персональных данных" ], "at": "2026-11-12 19:10:11", "document": "https://example.com/soglasie/", "revision": "2026-11-01" },
    "admin_url": "https://example.com/wp-admin/post.php?post=123&action=edit"

```

Проверка подписи на стороне CRM (PHP): `hash_equals( 'sha256=' . hash_hmac( 'sha256', $body, $secret ), $_SERVER['HTTP_X_TRUST_SIGNATURE'] )`.
Фильтры: `trust_notify_email` (получатели, тема, текст, заголовки), `trust_notify_telegram` (текст),
`trust_webhook_payload` (данные).

Почта: письма уходят через `wp_mail`, то есть через почту сервера. Чтобы письма не попадали в спам,
у домена должны быть записи SPF/DKIM для сервера, который отправляет почту, или нужен SMTP-плагин
(например, через почтовый ящик домена). Проверка — кнопка «Проверить уведомления».

Сообщение после отправки для форм без своего экрана успеха — «Настройки сайта → Формы → Сообщение
после отправки» (у окна звонка — свои тексты в «Блоках по умолчанию»).

**Кэш.** Страницы с формами можно кэшировать (токен скрипт берёт свежий). Адреса
`/wp-json/trust/v1/forms/*` и `/wp-admin/admin-post.php` кэшировать нельзя: ответы помечены
`no-cache`; если в Cloudflare включено правило «Cache Everything», эти адреса нужно из него исключить.

**Ключи reCAPTCHA v2:** google.com/recaptcha/admin → «Создать» → тип «Задача reCAPTCHA (v2)»,
вариант «Флажок „Я не робот“», домены — домен сайта (при переезде добавить и рабочий домен).
Ключ сайта и секретный ключ вводятся в «Настройках сайта → Формы»; секретный ключ никому не пересылать.

### Блоки

Каждый блок — папка `trust/blocks/<имя>/`, регистрируется автоматически (`Trust\Blocks`), только
при активном Secure Custom Fields:

| Файл | Что в нём |
|---|---|
| `block.json` | Название, описание, категория, иконка; `"acf": { "mode": "preview", "renderTemplate": "render.php", "blockVersion": 3 }`; `style` и `viewScript` |
| `fields.php` | Поля блока — массив без ключей; общие поля секции — `Trust\Blocks::section_fields()` (якорь, надзаголовок, H2, вводный текст) |
| `render.php` | Вёрстка; значения — `get_field( 'имя' )`; в редакторе `$is_preview` = true (интерактивные блоки раскрыты) |
| `style.css` | Стили блока, классы `.b-<имя>__…`; подключаются только на страницах с блоком (и в редакторе) |
| `view.js` | Скрипт блока на сайте (если нужен) |
| `example.php` | Значения для превью в списке блоков |

Версия стилей и скрипта блока — время изменения его файлов, поэтому после обновления темы браузер
и Cloudflare берут новые файлы. Ключи полей — `field_trust_block_<блок>_<поле>`.
Категории в редакторе — «Первые экраны», «Услуги», «Компания», «Списки», «Формы», «Кейс»,
«Текст и медиа» (пустые не показываются).

Картинки в тексте открываются на весь экран (мышью, Enter или пробелом) |
| `trust/image` «Картинка» | Картинка (JPG, PNG, WebP), «Alt» и «Декоративная картинка», описание, номер рисунка, ширина «Во всю ширину» (1200 px) или «По ширине текста» (960 px, как «Блок с текстом»), картинка для телефона (до 600 px — например, вертикальная схема; `<picture>` с размерами у `<source>`). Подпись «Рис. N»: номер — по порядку картинок на странице (`Trust\Blocks::figure_number()`), «0» — без «Рис.», можно задать свой. По клику картинка открывается на весь экран (на телефоне — картинка для телефона); без JavaScript ссылка открывает файл картинки. Без картинки блок на сайте не выводится; без alt — предупреждение в редакторе |

Заголовки во всех блоках редактора — только H2–H4 (`assets/js/editor-blocks.js`; H1 — первый экран).
Просмотр картинок на весь экран — `assets/js/lightbox.js` (скрипт `trust-lightbox`, подключают «Картинка»
и «Блок с текстом»): окно `<dialog>` с картинкой, подписью и кнопкой «Закрыть»; закрывается Esc,
кнопкой и нажатием мимо картинки, фокус возвращается на картинку.
Микроразметка цен: тарифы с «Ценой числом» попадают в `Service.offers` страницы услуги — один тариф
`Offer`, несколько — `AggregateOffer` (наименьшая и наибольшая цена, число тарифов, `RUB`).

Размеры картинок под форматы макетов — `Trust\Setup::IMAGE_SIZES` (ТЗ, п. 8.1): обложки статей
16:9 — `trust-cover-sm` 480×270, `trust-cover` 768×432, `trust-cover-lg` 1200×675 (обрезка).
Картинки, загруженные до включения темы, нужно один раз пересобрать (плагин «Regenerate
Thumbnails» или `wp media regenerate --yes` от владельца сайта).

Время чтения статьи — `Trust\Blog::reading_time()`: слова текста / скорость из «Настроек сайта →
Блоки по умолчанию → Блог» (по умолчанию 180 слов в минуту), вверх, минимум 1 минута. Дата
карточки — `Blog::date()` («5 ноября 2026»), рубрика — `Blog::rubric()`, список статей —
`Blog::index_url()`.

Общее для блоков: поле «Иконка» — `Trust\Icons::field()` (список с превью значков из спрайта,
`assets/js/icon-select.js`); картинка — `Trust\Blocks::image_alt_fields()` («Alt», «Декоративная
картинка»), вывод `Trust\Blocks::image()` (alt из блока, иначе из медиатеки, у декоративной пустой;
`srcset`), предупреждение в редакторе — `Blocks::image_alt_missing()` и `Blocks::editor_warning()`.
Отступы секций — `--section-y` в `main.css`: 64 px, на планшете 56, на телефоне 48 (правка заказчика,
в макетах 96), **у всех блоков одинаковые** — свой отступ блоку не задаётся (кроме первого экрана).
Корневая секция блока получает класс фона `trust-bg-white|lavender|violet|indigo`: у второго из двух
блоков одного фона подряд нет верхнего отступа (между ними один отступ, а не два).
Рисунок справа от шапки секции — `head-art.svg` в папке блока, вывод `Trust\Blocks::head_art()`,
поле «Картинка справа от заголовка» — `Blocks::head_art_field()` (обёртка `.section-top`, рисунок
`.section-art`; уже 900 px скрыт). Есть у «Что включает услуга», «Этапов работы», «Вопрос-ответ», «Выбора тарифа».

Кнопки блоков — поле «Ссылка» WordPress (`Trust\Blocks::buttons_field()` / `buttons()`): адрес —
страница, якорь раздела (`#vacancies`) или `#callback-modal` — такая ссылка в любом блоке или меню
открывает окно «Заказать обратный звонок».

Демо-контент страницы — список блоков в `demo/pages.php`:
`'blocks' => array( array( 'faq', array( 'title' => …, 'questions' => array( … ) ) ) )`;
`Trust\Blocks::serialize()` превращает значения в разметку блока. Третий элемент — разметка вложенных
блоков ядра (для «Блока с текстом»). Картинка в поле блока — `'{image:файл.jpg|alt}'` из `demo/images/`
(загружается в медиатеку один раз). В `example.php` блока с вложенными блоками — ключ `inner_blocks`.

Демо-статьи — `demo/posts.php` (5 статей из макетов). Обложка записи — `'thumbnail' => 'файл.jpg'`
из `demo/images/`: при импорте картинка один раз добавляется в медиатеку, `wp trust demo remove`
её удаляет. Пример WordPress «Hello world!» при импорте уходит в корзину, если его не меняли.

### Типы записей и адреса

| Тип | В админке | Адрес | Кто правит |
|---|---|---|---|
| `post` | Статьи | `/blog/<статья>/` | авторы и выше |
| `question` | Вопросы SEO | `/seo/voprosy/<вопрос>/` | авторы и выше |
| `case` | Кейсы | `/portfolio/<кейс>/` | редактор, администратор |
| `team` | Сотрудники | `/komanda/<сотрудник>/` | редактор, администратор |
| `review` | Отзывы | нет (выводятся в блоках) | редактор, администратор |
| `vacancy` | Вакансии | нет (страница «Карьера») | редактор, администратор |
| `lead` | Заявки | нет, только админка | редактор, администратор; вручную не создаются |

Таксономии: рубрики `/blog/rubrika/<рубрика>/`, теги `/blog/teg/<тег>/` (общие для статей и
вопросов); без публичных страниц — «Услуги» (кейсы, отзывы), «Отрасли» (кейсы), «Отделы»
(сотрудники, вакансии), «Темы вопросов». В редакторе они выводятся флажками.

- Архивов у типов записей нет: список выводит обычная страница с тем же адресом (`/portfolio/`),
  её вторая страница — `/portfolio/page/2/`.
- Ярлыки меняются в «Настройках сайта → Адреса» (только администратор). Префиксы рубрик и меток
  из «Настройки → Постоянные ссылки» тема не использует. Правила перезаписи обновляются сами,
  когда меняются ярлыки или типы записей в коде, — в том числе после обновления темы на сервере.
- Новые ярлыки записей и терминов и имена загружаемых файлов переводятся в латиницу по тем же
  правилам, что адреса макетов: «Карьера» → `karera`, «Данных» → `dannyh`, «Объём» → `obem`.
  Уже существующие кириллические ярлыки не меняются и продолжают открываться.

### SEO

**Группа «SEO»** — у страниц, статей, кейсов, ответов, сотрудников (боковая панель редактора) и у
рубрик и тегов (экран термина): предпросмотр в поиске, SEO title, meta description, H1, флажки
noindex и nofollow, canonical, заголовок, описание и картинка для соцсетей. Счётчики символов
краснеют после 60 (title) и 160 (description). В title и H1 можно `{site}` и `{sep}`.

| Что | Если поле пустое |
|---|---|
| Title | Шаблон из «Настроек сайта → SEO» (по умолчанию как в макетах: «{title} — [Бренд]», рубрика «… — блог [Бренд]», тег «#… — блог [Бренд]», сотрудник «… — автор блога [Бренд]», ответ «… — ответ SEO-специалиста [Бренд]»); на страницах 2, 3… — « — страница N» |
| Description | Анонс; у кейса — вводный текст, у сотрудника — «Коротко»; вводный текст первого экрана; начало текста (160 символов по слову); у рубрики и тега — описание |
| H1 | Заголовок записи, название рубрики или тега |
| Canonical | Адрес самой страницы; у страниц пагинации — их адрес; параметры вроде `?sort=` отбрасываются |
| Open Graph | Title, description; картинка — обложка, иначе картинка по умолчанию из настроек |

Robots: поиск и 404 — `noindex, follow`; флажки записи; теги, где статей и ответов меньше порога
из настроек (по умолчанию 3), — `noindex, follow`. Вкладка «SEO» в «Настройках сайта» — только
администратору: шаблоны title по типам, разделитель, порог тегов, картинка для соцсетей.

**Карта сайта** — встроенная в WordPress, `/wp-sitemap.xml`: страницы, статьи, кейсы, ответы,
сотрудники, рубрики (непустые) и теги от порога; без отзывов, вакансий, заявок и пользователей
(страница автора — страница сотрудника), без записей и терминов с флажком noindex. У записей —
дата изменения (`lastmod`).

**robots.txt** — виртуальный: текст из «Настроек сайта → SEO» (по умолчанию закрыты `/wp-admin/`,
кроме `admin-ajax.php`, `/?s=` и `/search/`) и строка `Sitemap:` — её тема добавляет сама.
Если в папке сайта лежит файл `robots.txt`, сервер отдаёт его, а не этот текст — такой файл нужно
удалить. Пока сайт закрыт в «Настройки → Чтение», карта отключена, а страницы получают `noindex`
(так WordPress работает с версии 5.3).

**Микроразметка** (`Trust\Schema\Graph`) — один `<script type="application/ld+json">` с `@graph`
в конце страницы (после блоков: блоки сами добавляют в граф свои данные). Сущности связаны через
`@id`, пустые поля не выводятся, `Review`/`AggregateRating`/`HowTo`/`JobPosting` не выводятся.

| Где | Сущности |
|---|---|
| Все страницы | `Organization` (или `ProfessionalService`, если выбран в «Настройках сайта → SEO» и заполнен адрес): бренд, логотип, телефон, email, адрес, соцсети (`sameAs`), `contactPoint`; `WebSite` |
| Каждая страница | `WebPage` или подтип: «О компании» — `AboutPage`, «Контакты» — `ContactPage` (+ координаты и ссылка на карту у организации), портфолио, команда, отзывы, вопросы, блог, рубрика, тег — `CollectionPage`, поиск — `SearchResultsPage`; имя, описание, язык, крошки, даты, обложка |
| Кроме главной и 404 | `BreadcrumbList` — те же пункты, что видимые крошки |
| Блок «Вопрос-ответ» | Страница становится и `FAQPage`; вопросы всех блоков страницы — в одном `FAQPage`, без повторов; в ответах — только простые теги |
| Тип «Услуга» | `Service`: H1, вид услуги (название в крошках), описание, адрес, `provider`, `areaServed` — «География услуг» из настроек (пусто — не выводится: работа по всему миру) |

Язык страниц — `ru` без страны: `<html lang="ru">` (как в макетах) и `inLanguage` в разметке
(`Trust\Setup::language()`); `og:locale` остаётся `ru_RU` — такой формат требует Open Graph.

Фильтр `trust_schema_graph` дополняет граф или отключает разметку (пустой массив). Разметка
статей, ответов, сотрудников, кейсов, списков и видео — вместе с их шаблонами и блоками.

**Alt картинок.** В медиатеке (режим списка) колонка «Alt»: у картинки без альтернативного текста —
«Нет — заполните»; в окне и на экране файла — предупреждение с подсказкой, что написать.

### Хлебные крошки и подсветка меню

Цепочки строятся сами (`Trust\Breadcrumbs`), на главной и на 404 крошек нет:

| Где | Цепочка |
|---|---|
| Страница | «Главная / родители / Страница»; у страницы без родителя — «Раздел в хлебных крошках» перед ней («Главная / О нас / Отзывы о нас») |
| Статья | «Главная / Блог / Рубрика / Статья» |
| Кейс | «Главная / Портфолио / Кейс» |
| Ответ | «Главная / SEO / Вопросы по SEO / Вопрос» |
| Сотрудник | «Главная / Сотрудники / Имя» (ссылка — на страницу «Команда») |
| Рубрика, тег | «Главная / Блог / Рубрика», «Главная / Блог / #тег» |
| Поиск | «Главная / Результаты поиска» |

- Блог — «Страница записей» из «Настроек → Чтение», а пока она не назначена — страница с адресом
  `/blog/`. Кейсы, ответы, сотрудники — через страницу-список с адресом из «Настроек сайта → Адреса».
- В группе «SEO» — раздел «Хлебные крошки»: «Название в хлебных крошках» (короткое: «Технический
  аудит» вместо «Технический аудит сайта»; у страниц, статей, кейсов, ответов, сотрудников) и
  «Раздел в хлебных крошках» (ссылка; только у страниц).
- Разметка — как в макетах: `nav` «Хлебные крошки», разделители скрыты от экранных дикторов,
  текущая страница — `aria-current`, ссылки не ниже 44 px. Сейчас крошки выводит стандартная
  шапка страницы; блоки первых экранов (этап 4) выводят их сами (`Breadcrumbs::render()`).
- **Подсветка меню:** пункт шапки подсвечивается, если его страница есть в цепочке — у кейса
  «Портфолио», у ответа «SEO», у статьи и рубрики «Блог».

### Типы страниц

«Страницы → Добавить» открывает окно **«Выберите тип страницы»**: 11 типов с описанием и
миниатюрой макета. Выбор ставит шаблон страницы (`templates/<тип>.php`) и вставляет набор блоков
по макету — только те блоки, которые уже есть в теме (наборы пополняются сами по мере появления
блоков). Закрыть окно (Esc) — останется «Обычная страница».

| Тип | Шаблон | Набор блоков (по порядку) |
|---|---|---|
| Услуга | `templates/service.php` | первый экран услуги, что включает услуга, этапы, преимущества, вопрос-ответ, кнопка связи, статьи блога |
| Главная / посадочная | `templates/landing.php` | первый экран раздела |
| Портфолио | `templates/portfolio.php` | первый экран, кейсы с фильтрами, отзывы (2 карточки), «Обсудим ваш проект» |
| О компании | `templates/about.php` | первый экран, направления, принципы, история, слово руководителя, сертификаты, клиенты, офис, CTA |
| Команда | `templates/team.php` | первый экран, руководство, команда по отделам, роли, приглашение, CTA |
| Отзывы | `templates/reviews.php` | первый экран с рейтингами, отзывы, видеоотзывы, письма, форма отзыва, CTA |
| Карьера | `templates/career.php` | первый экран, почему у нас, вакансии, отбор, стажировка, отзывы сотрудников, форма резюме |
| Контакты | `templates/contacts.php` | первый экран с каналами, офис, кому написать, форма, реквизиты |
| Документ | `templates/document.php` | первый экран документа, «коротко о главном», заголовок и абзац текста, реквизиты, другие документы |
| Вопросы SEO | `templates/questions.php` | первый экран с формой вопроса, оповещение, список ответов |
| Обычная страница | `page.php` | блок «Текст» |

- **Сменить тип** — панель «Тип страницы» справа (или стандартное поле «Шаблон»). Блоки при этом
  не пересоздаются; если страница пустая — предлагается вставить набор.
- **Первый экран и H1.** Если на странице нет блока первого экрана (или он удалён), шаблон
  выводит стандартную шапку с H1: страница без H1 невозможна.
- **Страница блога** («Настройки → Чтение → Страница записей») — в панели подсказка, что на сайте
  вместо её блоков выводится список статей.
- **Разрешённые блоки:** страницам — блоки темы и стандартные абзац, заголовок, список, цитата,
  картинка, таблица, разделитель, кнопки; статьям и ответам — текстовые блоки и блоки темы для
  статей; кейсам — блоки кейса и текстовые; всем — синхронизированные паттерны. «Кейсы с
  фильтрами» доступны только на «Портфолио», «Ответы специалистов» — только на «Вопросах SEO».
- Новый тип: шаблон в `templates/`, запись в `Trust\Page_Types::TYPES`, миниатюра в
  `assets/img/page-types/`.

### Поля кейсов и отзывов

| «Результаты» (до 4) | Первый экран кейса — все; карточки портфолио и «Похожие кейсы» — первые два |
| «Позиции в поиске»: запросы, регион и дата проверки | Блок «Наши проекты в топе» |
| «Команда проекта»: сотрудник и роль в проекте | Блок «Кто работал над проектом», «Команда проекта — N человек» |
| «Отзыв клиента» | Блок «Слово клиенту»; у отзыва — ссылка «Кейс проекта» |
| «Изображение записи», «Отрывок», «Услуги», «Отрасли» | Обложка и анонс карточки, фильтры портфолио |

**Отзыв** — классический экран (у отзыва нет текста в редакторе блоков, только поля). Вид
отзыва — «Текстовый», «Видео», «Благодарственное письмо» — показывает только нужные поля:
у видео — ссылка или файл, обложка, «О чём видео», длительность; у письма — скан. Без текста
(у текстового), скана (у письма), ссылки или файла (у видео) отзыв не сохранится. Пустой
заголовок заполняется именем и компанией. В свёрнутой части «Из формы на сайте» — контакты,
оценка и время согласий для отзывов из формы; на сайт они не выводятся. В списке отзывов —
колонки «Вид», «Автор отзыва», «Услуги», «Статус».

### Поля сотрудников, вакансий, вопросов

**Сотрудник** (классический экран; имя — заголовок, «Фото» — изображение записи, «Отделы» и
«Порядок» — панели справа): должность, «Руководство», год начала работы в профессии и «опыт в чём»
(стаж считается сам: «опыт в SEO — 11 лет»), «Коротко для карточки», «Об авторе», «Пишет о» —
теги и свои темы, соцсети (те же сети, что у компании), email для карточки руководителя,
пользователь WordPress. Пользователь связывается только с одним сотрудником; страница сотрудника —
это и страница автора его статей и ответов (`Trust\Team::for_user()`).

**Вакансия** (классический экран): «Принимаем резюме» (снят — вакансия скрыта с сайта), зарплата,
формат, опыт, город, «Коротко о вакансии», разделы описания — у новой вакансии уже добавлены
«Чем предстоит заниматься», «Что ждём от кандидата», «Что предлагаем»; пункты — с новой строки.

**Вопрос** (редактор блоков; заголовок — короткий вопрос и H1, текст записи — ответ специалиста):
в боковой панели — текст вопроса, имя (публикуется) и email (не публикуется) спросившего, дата
вопроса, «Отвечает» (сотрудник), дата ответа, «Статьи по теме из блога» (до 4), «Ссылка на ответ
отправлена» (заполняется само, шаг 5.7); «Темы вопросов» и «Теги» — панели редактора.

**Колонки и счётчики.** Сотрудники — фото, должность, опыт, отделы, руководство, пользователь,
порядок; вакансии — зарплата, формат, отделы, «Принимаем резюме»; вопросы — спросивший, специалист,
тема, статус. У пунктов меню «Заявки», «Вопросы SEO», «Отзывы» — число новых заявок и записей
на утверждении, как у «Комментариев».

Новые поля записей и терминов описываются в `inc/fields/content/<тип записи или таксономия>.php`
и добавляются в `Content_Fields::GROUPS`; имена полей начинаются с `trust_`.

### Меню в шапке

- Область «Шапка» (Внешний вид → Меню). Пункт с вложенными пунктами выводится кнопкой,
  открывающей выпадающий список; ссылка самого пункта в шапке не используется.
- Вторая строка у вложенного пункта — поле «Описание» пункта меню (включается в «Настройках
  экрана» вверху страницы меню). Если описания нет ни у одного вложенного пункта, список узкий,
  как «О нас» в макете.
- Разделитель над вложенным пунктом — CSS-класс `separator-before` в поле «CSS-классы» пункта
  (тоже включается в «Настройках экрана»).
- Текущая страница и её раздел подсвечиваются автоматически.
- Уже 1180 px меню открывается кнопкой-бургером: те же пункты, вложенные раскрываются по одному,
  внизу телефон, email и кнопка звонка. Без JavaScript мобильное меню показано раскрытым целиком.

### Подвал

- Колонки «Услуги» и «Компания» — меню «Подвал: услуги» и «Подвал: компания»; заголовок колонки —
  название меню (Внешний вид → Меню → «Название меню»).
- Ссылки на документы внизу — меню «Подвал: документы».
- Описание, плашки, юридическая строка (`{год}` → текущий год) и заголовок колонки контактов —
  «Настройки сайта → Подвал»; телефон, email, адрес, часы — «Настройки сайта → Контакты».
- Значки соцсетей (официальные, из Simple Icons, CC0) выводятся в колонке контактов, если в
  «Настройках сайта → Соцсети» заполнены ссылки. В макете соцсетей в подвале нет.

### Настройки сайта: права

Страница открывается пользователям с правом `edit_others_posts` (редактор и администратор).
Вкладка или поле с ключом `trust_cap` в описании (`inc/fields/settings/*.php`) видны только
пользователям с этим правом: так «Код интерактивной карты» доступен только администратору
(`manage_options`). Вкладки «Формы», «SEO», «Cookie и счётчики» и «Адреса» — только администратору.

Остальные тесты из раздела 18 ТЗ добавляются по ходу работ; каждый новый блок сверяется с макетом
в своём тесте и попадает в `npm test`.
