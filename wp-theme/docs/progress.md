# Ход работ и договорённости с заказчиком

Файл для продолжения работы (в том числе в новой сессии): где мы, что решено, что открыто.
План шагов — `docs/inventory.md`, раздел 13; устройство темы и команды — `README.md`.

## Как работаем

- Ветка `claude/happy-pascal-t7rcow`, pull request в `main` — только по просьбе заказчика.
- Работаем по шагам плана. После каждого шага: проверки на локальном стенде, коммит и push,
  короткий отчёт со скриншотами, команда для сервера, вопрос «можно ли следующий шаг».
- Заказчик сам выполняет команды на сервере. Обновление темы: `bash /root/trust-update.sh`,
  с новым демо-контентом — `bash /root/trust-update.sh --demo` (скрипт описан в README).

## Тестовый сервер заказчика

- VPS с FastPanel (Ubuntu 24.04, PHP 8.3, Apache за nginx), перед сайтом Cloudflare, SSL включён,
  сайт закрыт паролем. На сервере есть другие сайты — их не трогать, менять только папку сайта.
- WordPress 7.1.4 на русском, тема Trust активна, SCF установлен, постоянные ссылки `/blog/%postname%/`,
  `.htaccess` с правилами WordPress, адреса сайта переведены на https. Демо-контент импортирован.
- PHP2Shell (CVE-2026-109618/109619): пакеты php8.3 исправлены (`8.3.6-0ubuntu0.24.04.13`, обновлены
  23.10.2026), php-fpm и apache2 перезапущены после обновления — работают на исправленном PHP.
- Особенности: команды WP-CLI от имени владельца сайта запускать из папки сайта; `.htaccess` —
  через `rewrite flush --hard` с `apache_modules` (см. README).
- Индексация на тестовом сайте не закрыта (сайт под паролем). **При запуске рабочего сайта проверить
  «Настройки → Чтение»: индексация должна быть включена.**
- Тестовый сайт на поддомене другого домена; перенос на рабочий домен — `wp search-replace`,
  ключи reCAPTCHA на оба домена, свой счётчик, проверка почты (план переноса — в README на шаге 7.3).

## Открытые вопросы

- Логотип — ждём файлы от заказчика.
- Уведомления на сервере: заказчик вписал свой email в «Настройках сайта → Формы», проверка
  уведомлений — письмо не пришло (вероятно, у домена нет почтовых записей). Решено настроить почту
  при переносе на основной домен (см. «Напомнить в конце плана»). До этого заявки видны в админке;
  Telegram можно подключить уже сейчас.
- Ключи reCAPTCHA v2 — заказчик создаёт сам (google.com/recaptcha/admin, домен сайта) и вводит в
  «Настройках сайта → Формы»; в чат ключи не присылать. Пока ключей нет, капча не показывается.

- Отдел «Менеджмент» (в макете «Команда» — «Менеджеры», в «Карьере» — «Менеджмент»): взято одно
  название, заказчику сообщено на шаге 2.1.
- Значки соцсетей в подвале выведены в колонке контактов (в макете их нет) — заказчик пока не возражал.
- Демо-телефон «+7 (000) 000-00-00» в шапке и подвале — заглушка из макетов; заказчик заменит
  настоящим номером в настройках. Переводить ли демо-номер в формат +1 — не решено.

## Напомнить в конце плана (после шага 7.3)

- Почта при переносе на основной домен: письма о заявках на тестовом сервере не доходили.
  Настроить отправку — SPF/DKIM (и DMARC) домена для сервера или SMTP через почтовый ящик домена
  (README, «Формы и заявки → Уведомления»); проверить кнопкой «Проверить уведомления» на вкладке
  «Формы» и ответом из почты (письмо во «Входящих», не в спаме).

- Cloudflare при запуске на основном домене: если включено «Cache Everything», исключить
  `/wp-json/*` и `/wp-admin/*` (README, «Формы и заявки → Кэш»); проверить отправку форм через
  Cloudflare.
